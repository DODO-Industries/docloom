00

Text → embedding

The one borrowed, solved piece. A frozen sentence-transformer (all-MiniLM-L6-v2) maps text to a vector whose geometry encodes meaning. We don't reinvent this — we build a brain around it.

embeddingt = fφ(text) ∈ ℝ384
cosine similaritysim(a,b) = (a · b) / (‖a‖ ‖b‖)

embedding_service.py — 4-tier lookup (in-process → HTTP /embed → local SentenceTransformer → deterministic dummy) with a circuit breaker: after 2 failures it stops probing a dead endpoint for 120 s, so bulk ingest never stalls on socket timeouts.

01

HDC vector algebra

Hyperdimensional Computing. Represent concepts as very long random vectors where you can do algebra on meaning with cheap ops, and where random vectors are almost always near-orthogonal so distinct concepts don't collide. Bipolar: every element is −1 or +1, dimension D = 8000. Lives in HyperVectorCreation.py.

1.1 · Basis vector — a concept's fingerprint

Deterministic from the text via a hash, so it's identical across sessions with zero storage.

basisseed = SHA256(concept)[:8] hc = RNG(seed).choice({−1, +1})D
near-orthogonality𝔼[ (hc · hc′) / D ] = 0 , std ≈ 1/√D = 1/√8000 ≈ 0.011

Two independent random concepts collide with vanishing probability — that's why symbolic sim(dog,human) ≈ 0.

1.2 · HDC similarity

Bipolar vectors always have norm √D, so cosine collapses to a normalised dot product:

HDC cosinesim(a,b) = (a · b) / D

1.3 · Projection — the bridge between the two worlds

Random basis throws away learned meaning. A fixed Johnson–Lindenstrauss random matrix carries the 384-d embedding into 8000-d while approximately preserving angles.

random projectionP ∈ ℝD×d , Pij ∼ 𝒩(0, 1/d) eproj = P t ∈ ℝD # matrix seeded at 42, saved to disk hsemc = sign(P t) ∈ {−1,+1}D # semantic basis: angle-preserving

Because angles survive, sim(h_dog, h_puppy) stays high — semantics make it into HDC intact.

1.4 · Binding — permute (encode order / role)

A cyclic shift ρ scrambles reversibly and makes the result dissimilar to the original — so "A then B" ≠ "B then A".

bindρp(v) = roll(v, p) , sim(v, ρp(v)) ≈ 0

1.5 · Bundling — bundle (superpose a set)

Add the members and re-binarise; the result is similar to all of them at once. Two layers fall out — a continuous energy field and a discrete signature.

bundleF = ( Σi wi vi ) / ‖w‖ # Layer 2: analog field vector B = sign(F) # Layer 1: stable bipolar signature sim(B, vi) > 0 ∀ members # until overloaded → HDC capacity limit

1.6 · Fusion — semantic_fusion

Blend hard symbol and soft meaning by α.

fuseek = α hsymbolic + (1 − α) · P t # α=1 pure symbol · α=0 pure meaning

1.7 · Compression — pack_bipolar

One bit of real information per element; bit-pack + base64 takes ~40 KB → ~1.25 KB.

packbi = (vi + 1) / 2 , bytes = packbits(b) , str = base64(bytes)
▲ Decision on the table
Today the HDC signature is computed and stored but recall ranks on the continuous embedding — HDC is dormant potential. Do we make bind/bundle load-bearing (structural / relational queries, role-filler retrieval), or keep it a compact signature? This is candidate R&D-5.
02

Mass · energy · phase

Three scalars computed from the embedding give each memory its physical personality. (Computed in the weave path; on the live path mass may just be passed in, default 1.0.)

mass — semantic heavinessm = log(word_count + 1) · Σi |ti| , m ← max(0.1, m)
energy — mean magnitudeE = (1/d) Σi |ti|
phase — deterministic seed angleθ = ( atan2( Σi<d/2 ti , Σi≥d/2 ti ) + 2π ) mod 2π
◆ Why phase is seeded, not zero
If every shard were born at θ=0, the Kuramoto coupling would be a permanent no-op (sin 0 = 0) — an all-zero population is a degenerate fixed point it can never escape. Seeding real per-shard variation from the vector itself is what makes phase sync a live mechanic.
03

Scaffold & the momentum vector

One of the most original parts. Instead of storing a shard where its embedding says, we give it a resting socket derived purely from the seed + shard-id (zero disk reads to reproduce). Then mass warps the shard off its socket toward its true meaning: heavy memories snap to meaning, light ones stay near their procedural socket. Procedural generation of space, from one 64-bit number.

scaffold (micro socket)s = RNG( SHA256(seed ‖ "micro_" + shard_id) ) · 𝒩(0, 0.1)d
momentum = socket warped toward meaningw = m / ( SCAFFOLD_WARP + max(0, m) ) p = s + w · (t − s) , p ← p / ‖p‖

The seed core also has macro (per-crystal) and meso (per-bucket) offsets — the same trick at three scales. seed_core.py, storage_physics.py:34.

04

Routing & cellular division

The atlas keeps one lightweight centroid per crystal. A shard joins the crystal whose centroid is most similar to its momentum.

route — centroid gravity trackingtarget = argmaxc (p · ccentroid) / (‖p‖ ‖ccentroid‖)
centroid update — running centre of massccentroid ← (ccentroid · n + p) / (n + 1) , n ← n + 1
cellular division — split a full crystalcnew = (cold + 0.05 o) · ‖cold‖ / ‖cold + 0.05 o‖ # o = macro offset
✕ Hard-won bug: the division cascade
Ingest routes only to crystals with headroom. Routing to a full crystal used to spawn a new split on every hit — 1,798 files at 1M shards. Full crystals now still serve recall but never receive new shards.
05

LSH resonance-jump partition

Within one crystal there can be hundreds of thousands of shards. Random-hyperplane LSH lets each crystal self-organise into neighbourhoods: near vectors get near signatures (small Hamming distance), so recall jumps straight to the right neighbourhood instead of scanning O(n).

signature — sign of first 128 dims, 128 bitssig(v) = packbits( (sign(v[:128]) + 1) / 2 )
Hamming distance (popcount LUT)H(siga, sigb) = Σ popcount( siga ⊕ sigb )
assimilate vs accommodateHmin ≤ 32 → assimilate into that neighbourhood else & room (≤ 512 leaders) → accommodate — new leader else → nearest leader # never leave a shard unbucketed
✕ Critical correctness note (2026-07-13)
The signature must use the semantic vector t, not the scaffold-blended momentum p. Recall signatures the raw query (no per-shard scaffold); bucketing by momentum put identical content in different buckets and a shard could fail to retrieve its own vector. The fix took self-recall 1/7 → 7/7.
06

Storage append (the .loom file)

The vector + mass + metadata (text, bucket id) are appended to the crystal's binary log — never rewritten. A disposable .idx mmap snapshot holds the fast-access columns and can be rebuilt from the log anytime.

on-disk layoutuniverse.loom ("LUNI") each crystal .loom ("LOM2") ├ 1 KB header (seed, dim) ├ 64-byte header ├ segments: atlas, snapshot, … └ append-only shard / leader records └ append-only journal tail (id, float32 vector, mass, meta) .idx snapshot ("LIX2", mmap): offsets[] · mass[] · norms[] · contiguous float32 matrix · leaders[] · ids[] · bucket_ids[]

Crash-safe: torn records rejected, complete ones adopted. norms[] is precomputed so recall's cosine is one matrix-multiply, not a per-row norm. substrate_layout.py, universe_container.py.

07

Post-write: ledger, edge, one thought

Placing a shard also updates the living state:

  • RAM ledger — the awake set: activation, phase_angle, latent_position, velocity, hits + 7 cognitive fields. Capped at RAM_LEDGER_MAX = 50000; a stronger newcomer evicts the weakest resident (the loser sleeps safely on disk).
  • Journal — a 32-byte transaction record for crash recovery.
  • Sequential causal edge — "what came right before this" becomes a directed edge prev → this.
  • One cognitive tick — the shard is a percept; the shared field feels it (§8).
08

The cognitive tick — a "thought" as physics

The brain's continuous inner life. Whenever memories are touched, a shared latent field evolves like a physical system and each touched shard is a particle under forces. Bounded to a hot set (COGNITION_WORKING_SET_MAX = 128), so it's O(128²), never O(ledger).

Step 1 — input tensor (superpose what was touched)

inputu = ( Σsid intensitysid · xsid ) / ‖·‖

Step 2 — shared latent field: 2nd-order mass-spring-damper

field dynamicsvfield ← 0.8 vfield (drag) + 0.4 u (input force) + 0.2 (w − Lprev) (sync toward working mem) − 0.15 w (competitive inhibition) L ← (Lprev + vfield) / ‖·‖ # new latent field w ← ( (1−α) w + α L ) / ‖·‖ , α = 0.1 # working mem EMA

Step 3 — per-shard forces (dt = 0.1)

forcesflatent = (L − x) · 0.25 A # pull toward the field fcausal = Σnbr (xnbr − x) · 0.15 wedge # spring to causal neighbours frepel = Σ‖·‖<r (x − xo)/‖·‖ · k # push apart if too close v ← 0.7 v + (flatent + fcausal + frepel) dt , x ← (x + v dt)/‖·‖

Each shard then updates resonance = x·L (clipped), momentum = ‖v‖, energy ±, stability, attention.

Step 4 — field metrics

coherence — Kuramoto order-parameter analoguer = (1/N) Σi ( xi/‖xi‖ ) · x̄ ∈ [0,1] # r→1 one thought · r→0 scattered
entropy — field turbulenceS = clip( ‖L − Lprev‖ , 0, 1 )
energy budget — thermodynamics gating sleepbudget ← clip( budget + (0.15 Δr + 0.01 r) − 0.02 S , 0, 1 )

Step 5 — assembly crystallisation

Shards resonating with the field above 0.4, then filtered by a coherence gate (must cohere with the group's dominant member, ASSEMBLY_COHERENCE_MIN = 0.5), form a cognitive assembly. Successive distinct assemblies leave a causal edge.

✕ Why the coherence gate exists (bug #1)
The shared field is a blend of everything touched. Two unrelated topics both resonate with the blend and get bundled into one assembly → one topic-mixed semantic crystal (90–92% were mixed). The gate forces an assembly to be one concept.
09

The causal graph — "A causes B"

A directed graph over real shard-ids. Edges come from (1) sequential adjacency at ingest, (2) assembly transitions, (3) Hebbian co-occurrence at recall. This graph is what makes multi-hop / associative retrieval possible where plain cosine fails.

causal strength (temporal adjacency ≠ causation)strength = w · (1 − prediction_error) # reject if < CAUSAL_THRESHOLD = 0.1
edge update (averaging + frequency)wab ← (wab + strength) / 2 , freq += 1
forgetting stale edgesage > 60 s → w *= (1 − 0.1) ; prune if w < 0.05 ; drop orphan nodes

predictive_processing.py — the graph forgets associations that stop recurring.

10

Recall — querying the brain

A query text becomes q, then flows through the read pipeline in one of two modes:

ModeWhat runsCost
learn=True (default)decay, reinforcement, re-awakening, Kuramoto, cognitive tick, journaling — it remembers~200 ms
learn=False (serving)pure route → score → top-k; records a cheap trace, consolidates later in batches~1.4 ms

10.1 · Decay first — the forgetting curve

Activation decays exponentially since last recall, but a memory recalled often decays slower (log-buffered friction, an ACT-R effect).

decayλeff = λ / ( 1 + ln(1 + hits) ) A(t) = A0 · e(−λeff · Δt) # evict if A < SLEEP_EVICTION_LIMIT = 0.001

10.2 · Narrow the candidates

  1. Route q to the nearest crystal (cosine-to-centroid, as §4).
  2. If large (n > RECALL_FULL_SCAN_BELOW = 20000): signature q, Hamming against leaders, open the RECALL_SEED_LEADERS = 24 nearest neighbourhoods (∪ unbucketed safety net).
  3. Causal hop — expand candidates by walking the causal graph up to CAUSAL_HOP_DEPTH = 2 from the seed hits, so a causally-linked answer in a different bucket is reachable.
  4. Below threshold / legacy → full scan (identical results). Superseded shards are masked out here.

10.3 · Score the candidates (the physics)

Let cosi be the cosine of candidate i to the query (one matrix-multiply using precomputed norms).

gravitational attractionGi = ( ma · mi ) / max( (1 − cosi)² , ε ) , ε = 1e-4
wave excitation — dynamics, NOT rankinggaini = η · cosi · cos(θq − θi) , η = 0.4 Anewi = clip( Ai + gaini , 0, 1 ) # drives waking / reinforcement
★ FINAL RANKING SCOREscorei = Gi · ( 1 + RANK_ACTIVATION_WEIGHT · Ai ) , wA = 0.25
◆ Why phase is banned from ranking
Including the Kuramoto phase term in the score dragged R@1 from 0.50 → 0.43 — phase is memory dynamics, uncorrelated with relevance. Ranking is relevance-first (gravity monotonic in cosine) with only a monotonic activation nudge. This separation is the single most important scoring lesson in the codebase.
optional causal spread (HippoRAG-style, additive, opt-in)scorej ← max( scorej , spread_w · maxi→j [ scorei · min(wij, 1) ] )

Additive so a cosine-distant multi-hop answer (base score ≈ 0) can be lifted into top-k — a multiplicative factor could never raise 0. Off by default (CAUSAL_SPREAD_WEIGHT = 0) because sequential edges are noise on shuffled loads. Then take top-k by score.

10.4 · Plasticity (learning mode)

  • Reinforce winners: hits += 1, activation += RECALL_BOOST_VALUE = 0.15.
  • Re-awaken only the RECALL_MAX_WAKE = 256 strongest excited sleepers.
Kuramoto phase-locking — closed form, O(L) not O(L²)S1 = Σj aj sin θj , S2 = Σj aj cos θj Δθi = (K/N) ( cos θi · S1 − sin θi · S2 ) # = (K/N) Σ aj sin(θj−θi) θi ← ((θi + Δθi + π) mod 2π) − π , K = 0.1

The sine angle-subtraction identity turns the O(L²) pairwise sum into two global sums — identical result, linear cost. Co-active memories gradually synchronise phases: a soft binding signal. recall then decodes text only for the top-k winners and feeds them back as a percept.

11

Sleep — consolidation (NREM + REM)

When the brain goes idle after activity, recurring concepts (assembly frequency ≥ 3) are compressed into a new semantic crystal — the experiment the field research says nobody has run at this scale with continuous dynamics.

  • Trigger: idle ≥ 120 s and ≥ 50 shards since last sleep (or forced).
  • NREM: reinforce causal edges + activation among members.
  • REM: LLM-synthesise a faithfulness-constrained summary (template fallback), embed it, ingest as a new shard.
semantic crystal placementvnew = ( (1/n) Σi xi ) / ‖·‖ , mnew = min(5.0, 1.5 + 0.1 n)

Sources are marked superseded — deprioritised in recall's fast path, never deleted; decode_cluster() always sees them (provenance). A synthesis_mode flag ("llm"/"template") is stamped for a later faithfulness audit. maybe_sleep_cycle.

12

Persistence — one file, crash-safe

All state folds into a single universe.loom: header (seed/dim), named segments (atlas, snapshot, cognitive-state bins), and a typed append-only journal tail. Crystal registrations + ledger transactions are journaled immediately (survive a crash); the heavy snapshot folds in at checkpoint cadence. Boot replays journal + snapshot to rebuild the RAM ledger in ~1 s. Legacy loose-file brains auto-consolidate on first boot (originals moved to legacy_backup/, nothing deleted).

Worked example (with numbers)

Ingest "the dog ran home" (d = 384, Σ|ti| = 30, 4 words):

writemass m = ln(4+1) · 30 = 1.609 × 30 ≈ 48.3 # heavy → snaps to meaning warp w = 48.3 / (1 + 48.3) = 0.98 # p ≈ t route → crystal_1.loom ; bucket: nearest leader H = 20 ≤ 32 → assimilate ledger ← {activation: 1.0, phase: 2.1, hits: 0} ; causal edge prev → this ; tick

Query "where did the animal go?" → q:

readcos(q, t) = 0.55 G = (1 · 48.3) / max((1 − 0.55)², 1e-4) = 48.3 / 0.2025 ≈ 238.5 score = 238.5 · (1 + 0.25 · 1.0) = 298.1 # → lands in top-k

If "the dog ran home" and "the dog ate food" were ingested adjacently, the causal hop also pulls in "ate food" though it's less cosine-similar — the associative win.

Designing a loom-native retrieval algorithm

The current score is G·(1 + 0.25·A) — gravity is monotonic in cosine, so ranking is essentially cosine re-ranking. The substrate computes a dozen rich signals (mass, phase coherence, a causal graph, field resonance, supersession, decay) that the ranking never fully uses. A retrieval algorithm native to the loom would fuse them — here are five candidates, each with the equation, what it reuses, the hypothesis, and a kill condition.

◆ The governing principle
Physics only pays rent when the answer is not the query's nearest neighbour — multi-hop, temporal, contradiction regimes. Every candidate below should be evaluated in that regime, with a matched-compute cosine (and ideally HippoRAG-2 PPR) baseline. Pre-register the negative result as first-class.
headline bet

R&D-1 · Personalized PageRank over the causal graph

Reuses: the existing causal graph + cosine seeds. Replaces: the single-round additive spread.

The current spread is one hop, taking the strongest neighbour's score. Full PPR (HippoRAG-2's proven mechanism, +9.5–20 pts on multi-hop) diffuses relevance over the whole graph until convergence.

power iteration to fixed pointπ = (1 − α) · s + α · M · π # s = cosine-relevance seed, normalised M = column-normalised causal adjacency (edge weights wij) scorei = Gi · (1 + β · πi) # α ≈ 0.5, ~10–20 iterations

Hypothesis: beats the 1-round spread on 2-/3-hop chains where the answer is ≥2 edges from any direct match. Kill if: no gain over 1-round spread on MuSiQue / 2Wiki at matched candidate-set size.

speculative

R&D-2 · Query-as-oscillator — Kuramoto relevance

Reuses: per-shard phase θi and the closed-form Kuramoto update — currently dynamics-only, banned from ranking. This is the experiment where it might become causally load-bearing.

Inject the query as an oscillator with natural phase θq and couple it (weighted by cosine) to the candidates for a few steps. Relevance = how tightly a candidate phase-locks to the query.

phase-lock relevancerun T steps: θ̇i = K · cosi · sin(θq − θi) locki = cos(θq − θi(T)) ∈ [−1, 1] # 1 = fully entrained scorei = Gi · (1 + γ · max(locki, 0))

Hypothesis: shards that co-fire with the query's context (not just its content) entrain faster, surfacing context-consistent answers cosine misses. Honest prior: oscillator terms have never beaten cosine on QA anywhere — treat as high-risk. Kill if: no lift over R&D-1 on any regime after phase is properly seeded.

strong & buildable

R&D-3 · Energy-descent retrieval (physics-native re-ranker)

Reuses: the mass-spring-damper the cognitive tick already runs. Retrieval becomes finding the low-energy set, not the top-cosine list.

Treat the returned set S as particles in a potential well: attracted to the query, coupled through causal springs, repelling each other for diversity (an MMR-like objective, but grounded in the substrate's own forces).

select S to minimise total energyU(S) = − Σi∈S Gi # query attraction (relevance) − Σi,j∈S wij (xi·xj) # causal cohesion (evidence chains) + η Σi,j∈S max(0, τ − ‖xi − xj‖) # repulsion → diversity greedy: add argmini ΔU(S ∪ {i}) until |S| = k

Hypothesis: returns a coherent evidence set for multi-hop QA rather than k near-duplicates of the top hit. Kill if: no answer-recall or downstream-QA gain vs cosine top-k + MMR at equal k.

quick win

R&D-4 · Learned fusion weights (stop hand-tuning)

Reuses: every signal already computed — makes the weighting empirical instead of guessed.

All the coefficients (0.25, β, γ, η…) are hand-set. Fit a tiny log-linear ranker on labelled (query, relevant-shard) pairs — cheap, interpretable, and it tells you which physics pays rent per regime.

log-linear score, weights learned by logistic rankinglog scorei = a·log Gi + b·πi + c·Ai + d·ρi + e·locki + f·(−agei) # ρ = field resonance, π = PPR, lock = phase; fit a..f to maximise NDCG

Payoff: the fitted weights are themselves a research result — a term whose weight fits to ≈0 is decorative and can be cut. Kill if: learned weights collapse to "a≈1, rest≈0" (= cosine) across all regimes.

latent frontier

R&D-5 · Wake the HDC world (structural / role-filler queries)

Reuses: the dormant 8000-d HDC signatures (§1) — currently stored, never queried.

HDC bind/bundle can answer questions cosine can't phrase: "find memories where X plays the role of agent", analogical "A is to B as C is to ?". Add an HDC channel that unbinds a role from a bundle.

role-filler probe via unbindingfiller ≈ ρ−role( Bshard ) # invert the permutation that bound the role hdc_simi = (filler · hquery) / D scorei = Gi · (1 + g · max(hdc_simi, 0))

Hypothesis: unlocks a query class (structured / relational) the continuous index cannot serve — a capability win, not an accuracy win on existing benchmarks. Kill if: no structured-query benchmark shows HDC beating a cosine+rerank baseline; otherwise it's the differentiated moat.

▲ My recommendation for sequencing
Build R&D-4 (learned weights) first — it's cheap and tells you which of the others is worth it. In parallel ship R&D-1 (PPR) — it's the evidence-backed headline win. Treat R&D-2 and R&D-5 as research bets gated on R&D-4's weights actually loading them. R&D-3 is the elegant "only-loom-could-do-this" story if multi-hop evidence-set quality matters downstream.

The one-paragraph strategy

Don't build a faster FAISS — you'll lose. Build the retrieval algorithm that only a living substrate can run: PPR over a self-grown causal graph (R&D-1), an energy-selected coherent evidence set (R&D-3), fused by learned weights that prove which physics matters (R&D-4), evaluated in the multi-hop / updating regime where the answer is never the nearest neighbour — then push for the positive-slope curve under adversarial growth. That combination is unclaimed in the field and is what a thesis (or paper) is made of.
